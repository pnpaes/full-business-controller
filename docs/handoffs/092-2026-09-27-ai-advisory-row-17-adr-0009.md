# 092 — 2026-09-27 — AI-assisted advisory: review foundation + scheduled run (row 17, `ADR-0009`)

Status: uncommitted at authoring; branch `main`. Migration `0075`.

## What was built.

`ADR-0009` was accepted 2026-09-27 (`DEC-142`, advisory-only, provider-agnostic), unblocking
row 17 (`FCST-004`). Delivered in two slices:

### 17a — the review foundation (migration `0075`)

- `ai_analysis_run` (append-only provenance: kind, provider, model, prompt version, input scope +
  snapshot, output, status, token counts, `numeric(19,4)` cost estimate, audit columns) and
  `ai_suggestion` (mutable state machine `proposed`→`approved`/`rejected`/`superseded`, plain-uuid
  `decided_by`, `reason`, index on `analysis_run_id`). **Deviation recorded:** `organization_id` was
  added to `ai_suggestion` too (the data dictionary omits it), per the `DEC-061` tenancy convention.
  Checks: non-blank reason on reject/supersede, decided-by/at paired with a non-`proposed` state;
  append-only triggers on the run only. Public tables **99 → 101**.
- Application (`packages/application/src/ai/**`): `recordAiAnalysisRun`, `recordAiSuggestion`,
  `decideAiSuggestion` (reason required on reject; audited `ai.suggestion.approved|rejected`; only
  `proposed` decidable), `listAiSuggestions`, `findAiAnalysisRun`, Postgres adapter + fake.
- HTTP `apps/web/app/api/v1/ai/**`: `GET /ai/suggestions` (state filter, paging; never exposes the
  raw snapshot/output/cost), `POST /ai/suggestions/[id]/approve`, `/reject` (reason required).
  `AI_READ_ROLES` = owner/GM/finance/admin; `AI_DECIDE_ROLES` = owner/GM/admin (provisional,
  `DEC-101`); fail-closed limiter; **approving takes no action** (advisory only).
- UI `/ai` review queue (state filter defaulting to `proposed`, paging, approve/reject with a
  confirmation modal and a required reason, model output rendered as plain text), nav entry.

### 17b — the provider + scheduled run

- `LlmPort` (`packages/application/src/ai/llm.ts`) + the OpenAI-compatible adapter
  (`packages/jobs-runtime/src/llm-adapter.ts`: `POST LLM_API_URL`, bearer `LLM_API_KEY`, bounded
  ~30 s timeout, fail-closed when not configured, provider label = URL host only).
- `registerAiAdvisorySchedule` (`packages/jobs-runtime/src/ai-advisory.ts`), cron
  `outbox.maintenance.ai_advisory`. **Guard order:** kill switch (`AI_ADVISORY_ENABLED`, default
  false) → adapter configured → monthly/per-run cost caps (`sumAiAnalysisRunCosts`) → call; provider
  failure records a `failed` run and never throws. On success it writes one run plus `proposed`
  suggestions; **no external publish, no auto-apply**. The LLM call happens **outside** the DB
  transaction; the run + suggestions are written in one transaction.
- Env: `AI_ADVISORY_ENABLED` (default false), `AI_ADVISORY_CRON`, `LLM_API_URL`, `LLM_API_KEY`
  (secret), `LLM_MODEL`, `AI_MONTHLY_COST_LIMIT`, `AI_PER_RUN_COST_LIMIT` (decimal ≤4 dp).
- `actorId` widened to `string | null` on the 17a commands (system runs use `created_by = null`).
