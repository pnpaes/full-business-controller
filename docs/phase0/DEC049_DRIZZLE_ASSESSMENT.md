# DEC-049 — drizzle-orm advisory assessment

Assessment only; no code was changed. Recorded 2026-09-19 to support the DEC-049
decision (`12_OPEN_DECISIONS.md`) and the pin in `docs/adr/0002-orm-and-migrations.md`.

## Advisory

- **GHSA-gpj5-g38j-94v9 / CVE-2026-39356, CWE-89, CVSS 7.5 (high).** `escapeName()`
  fails to double identifier delimiters; exploitation requires untrusted input reaching an
  identifier/alias builder (`sql.identifier()`, `.as(...)`, dynamic column/table/alias
  names).
- **Affected:** `drizzle-orm <0.45.2` and `>=1.0.0-beta.2 <1.0.0-beta.20`.
  **Patched:** `0.45.2` and `1.0.0-beta.20`.
- Current pins: `drizzle-orm 0.38.4`, `drizzle-kit 0.30.6`
  (`packages/persistence/package.json:16,19`; single copy in `package-lock.json`).

## Reachability today: not reachable

Every identifier/alias construction site in the repo is code-controlled and every
runtime value is a bind parameter: the `lower(btrim(...))` lookup and `failed_login_count + 1`
in `packages/persistence/src/repositories/users.ts`; the replay compare-and-set and
`array_remove(... = any(...))` in `repositories/totp.ts`; and the static-table selects,
joins and upserts across the other repositories. There are **zero** occurrences of
`sql.identifier()`, dynamic `.as(...)`, `alias()`, or dynamic `select`/`from`/`orderBy`.

The single `sql.raw` is `enumCheck` (`packages/persistence/src/schema/columns.ts`), which
builds **string literals** (not identifiers) from the code-controlled `vocabularies.ts`
constants and escapes quotes; it runs when schema/DDL is built, never from request input.

**It becomes reachable** with any feature that derives an identifier or alias from request
input — a report builder selecting columns, dynamic sort/filter, or import mapping. That is
exactly the DEC-049 trigger, and the reason the upgrade must land before such a surface.

## Recommended action

Upgrade `drizzle-orm` to **0.45.2** and `drizzle-kit` to **0.31.10** in a dedicated,
schema-neutral commit, now — the repo is pre-data and pre-production and the migration
format is unchanged, so this is the cheapest it will be. Do not defer to the DEC-049
floor, and do not treat it as an incident.

Expected delta:

- **Tests:** drizzle 0.44 wraps every driver error in `DrizzleQueryError` with the original
  in `.cause`, so the two append-only assertions in
  `packages/persistence/src/repositories/audit.test.ts` must assert on `.cause` (or
  `/Failed query/`). No production query code should change.
- **Migrations:** `_journal.json`/snapshots are `version: "7"` in both generations and the
  migrator hashes raw SQL with sha256, so a ledger at 0003 is not re-run. `npm run db:generate`
  must report **"No schema changes"** — investigate a spurious diff before committing.
- **drizzle-kit** swaps its loader (`esbuild-register` → `tsx`) and esbuild version; the
  pre-deploy migrator image ships devDependencies, so re-verify migration in the image.

Verification: `npm ci`, the full `lint`/`typecheck`/`test`/`build`/`format:check` chain,
`db:generate` (no diff), an empty-database replay (0000–0003) and a no-op re-run against a
migrated database, `npm audit --omit=dev` (expect 0), and the container build plus
`/api/health`.

Rollback: the bump is `package.json` + `package-lock.json` only — `git revert` plus
`npm ci`. Keep it a **separate schema-neutral commit**: a migration generated by 0.31 may
not be re-readable by 0.30.6, so never mix the two in one commit.

Also add a zero-dependency ESLint `no-restricted-syntax` tripwire banning
`sql.identifier`, `sql.raw` and dynamic `.as(...)`, so DEC-049's "identifiers stay
code-controlled" rule is enforced mechanically rather than by review.

Never target `1.0.0-beta.*` below `beta.20`, and do not take `1.0.0-rc.*`.
